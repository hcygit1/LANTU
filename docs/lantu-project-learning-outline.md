# LANTU 项目学习目录

这份目录是学习 LANTU 当前交互终端实现的主线。后续每个章节先确认目录，再按确认后的问题逐个学习。

## 学习规则

- 只保留当前章节最核心的问题。
- 同一个知识点只归属于一个问题，不在其他章节重复展开。
- 按真实执行顺序组织：对象创建 → 数据流转 → 状态变化 → 异常处理。
- 每个问题先形成面试版本，再根据需要展开代码细节。
- `-p` 非交互模式和 Remote 模式暂不纳入主学习线。

## 第一部分：交互终端运行架构

核心链路：

```text
main / _main
    → build_interactive_runtime
    → InteractiveRuntime
    → Agent Loop
```

学习重点：程序入口、运行时依赖组装、生命周期管理，以及 Agent 如何使用运行环境。

## 第二部分：Agent 核心执行引擎

核心链路：

```text
用户输入
    → 准备模型输入
    → 调用模型
    → 判断是否调用工具
    → 执行工具并进入下一轮
    → 返回最终结果
```

学习重点：交互终端中一次用户任务的完整执行过程。

## 第三部分：工具、权限与加载模式

本章按一次工具调用的真实顺序学习，固定为以下 7 个问题：

1. LANTU 如何统一定义和注册不同工具？
2. 当前哪些工具对模型可见？
3. 模型如何获得并理解工具定义？
4. 模型返回工具调用后，LANTU 如何完成分发？
5. LANTU 如何控制工具执行权限？
6. 多个工具调用如何调度和执行？
7. 标准模式和渐进模式有什么区别？

本章不单独展开 MCP、ToolSearch、Schema Epoch 和工具结果裁剪：

- MCP 归入第七部分扩展能力。
- ToolSearch 和 Schema Epoch 作为渐进模式的实现细节，在第 7 个问题中说明。
- 工具结果大小控制和落盘归入第四部分上下文管理。
- 工具调用结果回填属于第二部分 Agent Loop 总流程，后续不重复拆题。

## 第四部分：上下文与前缀缓存

本章只回答一个核心问题：

> LANTU 如何通过上下文管理优化前缀缓存命中率？

按以下顺序展开：

1. 确定模型请求的上下文结构。
2. 固定 System Prompt 和工具 Schema 等稳定前缀。
3. 控制过大的工具结果。
4. 使用 File Ledger 管理文件读取状态。
5. 压缩历史上下文并重建运行状态。
6. 通过真实 API 测试验证缓存优化效果。

## 第五部分：Session Journal 与 Lens

本章只回答一个核心问题：

> LANTU 如何记录 Agent 执行过程，并实现崩溃恢复和故障诊断？

按以下顺序展开：

1. Journal 如何表示一次完整执行？
2. Journal 如何保证记录可靠？
3. LANTU 如何从 Journal 恢复会话？
4. Lens 如何把流水事件转换成可分析数据？
5. Lens 最终能解决什么问题？

核心数据流：

```text
定义事件
    → 可靠写入 Journal
    → 从 Journal 恢复会话
    → Lens 构建分析视图
    → 诊断、回放和导出
```

## 第六部分：多 Agent 协作

本章只回答一个核心问题：

> LANTU 如何组织多个 Agent 协作完成一个复杂任务？

按以下顺序展开：

1. LANTU 为什么需要多个 Agent？
2. 子 Agent、Team 和 Task 分别是什么？
3. 任务如何分配给子 Agent？
4. 多个 Agent 如何通信和共享结果？
5. 如何通过 Worktree 隔离并行修改，并处理失败恢复？

核心数据流：

```text
创建子 Agent
    → 分配任务
    → 隔离工作环境
    → Agent 间传递消息
    → 汇总结果
    → 清理和恢复
```
