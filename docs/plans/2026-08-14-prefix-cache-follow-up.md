# LANTU 前缀缓存后续计划

日期：2026-08-14

## 已完成基础

- System Prompt 已固定，不再随轮次重建。
- 工具结果在进入对话历史前完成单项和整批大小控制，历史内容保持不可变。
- `run` 与 `run_to_completion` 已统一到同一个 Agent 核心循环。
- TUI 已增加等待 Spinner 和明确的权限输入选项。

## 未完成任务

以下任务按依赖顺序实施，完成前一项后再进入下一项。

### 1. 静态提醒去重

目标：相同的 deferred tools、Hook 和模式提醒不再每轮重复追加到上下文。

实现要点：

- 为提醒生成稳定标识，记录当前 Epoch 已注入的提醒。
- 内容没有变化时不追加；内容变化时追加新版本，不修改旧消息。
- 压缩后根据保留结果重新建立提醒状态。

完成标准：连续多轮请求中，相同提醒只出现一次；工具集合变化后只追加一次新提醒。

### 2. 动态工具 Schema Epoch

目标：ToolSearch 动态加载工具时，明确管理工具 Schema 变化造成的缓存边界。

实现要点：

- 为当前已加载工具集合计算稳定的 Schema 指纹和 Epoch ID。
- 同一 Epoch 内保持 System Prompt、工具顺序和 Schema 内容不变。
- 工具集合变化时开启新 Epoch，不回写或插入旧历史。
- 在 Journal 中记录 Epoch 变化及原因，供 Lens 和评测分析。

完成标准：同一 Epoch 的请求前缀稳定；只有真实的工具集合变化会创建新 Epoch。

### 3. 文件 Ledger

目标：避免重复读取相同文件内容，同时保留完整、可审计的读取轨迹。

实现要点：

- 按规范化文件路径记录内容哈希、文件版本、已读取行范围和对应 Journal 事件。
- 文件内容和读取范围未变化时复用已有证据，不重复把全文放入上下文。
- 文件变化或请求范围未覆盖时重新读取，并追加新的 Ledger 记录。
- Ledger 只影响上下文投影，不删除 Journal 中的历史读取事件。

完成标准：重复读取不增加大段上下文；文件变化后不会错误复用旧内容。

### 4. Repo Map

目标：为首次理解项目和跨文件定位提供稳定、紧凑的代码库地图。

实现要点：

- 生成目录、主要模块、入口和关键符号的紧凑表示。
- Repo Map 使用稳定排序和内容指纹，仓库未变化时保持字节级稳定。
- 与文件 Ledger 配合：Repo Map 负责定位，工具按需读取具体文件。
- 仓库变化时增量更新，并进入新的上下文 Epoch。

完成标准：常见定位任务减少搜索和重复读取，同时不明显增加首轮上下文成本。

### 5. 缓存命中评测

目标：证明上述架构能提升缓存命中和响应效率，同时不降低任务成功率。

实现要点：

- 使用同一模型、相同任务、相同提示词，对比优化前基线与优化后版本。
- 记录任务成功率、缓存读取 Token、缓存创建 Token、缓存命中率、首 Token 延迟、总耗时和成本。
- 增加长会话、多轮工具调用、重复读文件和动态加载工具四类专项任务。
- 保留少量 Terminal-Bench 任务作为基础能力回归，不把它作为缓存优化的主要结论。
- 评测产物保存在本地 `jobs/`，仓库只提交汇总报告和可复现配置。

完成标准：任务成功率不下降，缓存命中率和首 Token 延迟有稳定、可重复的改善。
