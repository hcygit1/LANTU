# ZG 仓库检索 A/B 测试报告

## 实验信息

- **测试日期**：2026-09-10
- **目标**：比较传统搜索/暴力读取与 zvec-grep 混合检索在定位准确性和上下文开销上的差异。

## 环境

- zvec-grep：0.2.2
- 本地嵌入模型：`local/potion-code-16m-v2`
- 索引：319 个文件、3,236 个实体、0 失败
- MCP：`http://127.0.0.1:7999/mcp`，full toolset
- 查询集：2 个自然语言语义查询、2 个精确查询

## 结果

| 指标 | 本地 rg 基线 | ZG MCP 实验组 |
|---|---:|---:|
| 成功定位 | 2/4 | 4/4 |
| 总耗时 | 95.76 ms | 623.65 ms |
| 语义查询后端 | rg | zvec_grep_search |
| 精确查询后端 | rg | zvec_grep_rg |

基线 `rg` 无法用自然语言定位两个概念问题，只完成两个精确查询。ZG 完成全部查询，但向量检索有额外推理开销。

## 结论

ZG 在该小型固定查询集上将定位成功率从 50% 提升至 100%，证明语义检索补足了 `rg` 只能按文本匹配的限制。ZG 耗时更高，因此精确查询仍应使用 `zvec_grep_rg`。该实验只验证检索定位，尚未通过完整 Agent 轨迹测量工具调用次数和 Token 节省。
