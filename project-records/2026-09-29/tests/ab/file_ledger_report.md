# File Ledger A/B 测试报告

## 实验信息

- **测试日期**：2026-09-10
- **测试目标**：验证 File Ledger 是否减少重复文件内容注入和输入上下文 Token。
- **测试脚本**：`bench/lantu_validate.py --turns 12`
- **测试类型**：离线、确定性、固定模型响应
- **任务集**：LANTU 固定代码阅读会话，共 12 轮、24 次模型请求。
- **网络/API Key**：不需要。模型响应由脚本固定，避免模型随机性影响组件对比。

## A/B 配置

| 项目 | Baseline | Optimized |
|---|---|---|
| File Ledger 去重 | 关闭 | 开启 |
| 任务和模型响应 | 相同 | 相同 |
| 工具和上下文限制 | 相同 | 相同 |
| 压缩场景 | 相同 | 相同 |

生产代码默认 `file_ledger_enabled=True`。关闭开关只用于构造基线，不改变默认运行行为。

## 主要结果

| 指标 | Baseline | Optimized | 差异 |
|---|---:|---:|---:|
| 模型请求数 | 24 | 24 | 0 |
| 估算输入 Token | 355,363 | 348,449 | -6,914 |
| 重复读取避免 | 0 | 1 | +1 |
| 持久化工具结果 | 1 | 1 | 0 |
| 错误数 | 0 | 0 | 0 |
| 可复用前缀比例 | 92.0% | 92.5% | +0.5 个百分点 |

计算：

```text
Token 节省 = 355,363 - 348,449 = 6,914
Token 降低比例 = 6,914 / 355,363 = 1.9%
```

## 强制压缩场景

两组均执行一次强制压缩，结果均为 `errors: 0`：

- Baseline：443,203 估算输入 Token，89.5% 可复用前缀比例。
- Optimized：436,289 估算输入 Token，89.9% 可复用前缀比例。
- 优化组相对节省：6,914 估算输入 Token。

## 结论

在这组固定任务中，File Ledger 成功识别并抑制了 1 次重复文件读取，使估算输入 Token 降低 1.9%，同时没有引入错误或改变模型请求次数。该结果证明机制有效。

## 限制

本次任务只有一次可去重的重复读取，因此不能将 1.9% 视为通用收益。后续应增加不同文件、不同代码区间和多次重复读取，并在相同条件下重复运行后报告均值和方差。端到端缓存收益需使用真实 Provider 的在线测试单独测量。
